# Задание для облачного агента: DRM Reliability Toolkit v0.2

## Цель
Подготовить DRM Reliability Toolkit к честному сравнению с baseline и к возможной упаковке. Результат — один PR в этот приватный репозиторий. Ничего не публиковать.

## Контекст
- Сейчас в репозитории v0.1: скилл `skills/drm-audit/SKILL.md` (аудитор чужого текста), 9 ручных кейсов в `tests/evaluation_cases.md`, рубрика `tests/scoring_rubric.md`.
- Гипотеза продукта: DRM-аудит находит больше реальных проблем в ИИ-текстах без роста ложных срабатываний, чем простой промпт «Analyze this text for errors and unsupported claims». Гипотеза НЕ доказана.
- Позиционирование: проверка ИИ-отчётов и исследований на перегибы (unsupported certainty, ложная причинность, evidence mismatch). Не «аудит сознания ИИ».

## Что сделать

### 1. Расширить тестовый набор (`tests/evaluation_cases.md` → v0.2)
- Сохранить 9 существующих кейсов без изменений в тексте.
- Добавить 12–20 новых кейсов, синтетических и разнообразных: отчёты о багах, аналитика, бэктесты, научные резюме, код-ревью, самоотчёты ИИ.
- Минимум 1/3 кейсов — ловушки на ложные срабатывания (текст корректен, проблем нет или они уже оговорены автором).
- Для каждого кейса: вход, ожидаемые находки (список), ожидаемое отсутствие находок, тип (issue / trap / scope-change / ambiguity).
- Все примеры придумывать самому. Не использовать реальные персональные данные, ключи, реальные диалоги.

### 2. Скрипты прогона и слепой оценки (`eval/`)
- `eval/run_cases.py`: для каждого кейса и каждого метода (`drm`, `baseline`) вызывает модель через API, сохраняет сырой ответ в `eval/runs/<дата>/<метод>/<case_id>.md`. Модель, версия, температура, промпт — параметры в конфиге. Ключ — из переменной окружения, в репозиторий не писать. Запуск последовательный, без параллелизма.
- `eval/blind_pack.py`: перемешивает выводы, заменяет метод случайным ярлыком (A/B), пишет ключ соответствия в отдельный файл `key.json`, который оценщик не открывает.
- `eval/score_sheet.csv`-шаблон по рубрике (5 измерений 0–2) и `eval/aggregate.py`, считающий баллы по кейсам и измерениям, с разбивкой отдельно по ловушкам.
- Не запускать реальные прогоны без явного указания владельца. Протестировать скрипты на заглушке (mock-ответы).

### 3. Новый скилл `skills/drm-contract/SKILL.md`
Режим для модели во время ответа. Исходный текст контракта: маркеры `[SIM]`, `[LIMIT]`, `[PARADOX]`, `[PARTNER]`; порядок: Понимание запроса → Гипотезы/допущения → План рассуждений → Ответ → Альтернативы → Ограничения → Следующий эксперимент.
Обязательные правки:
- Заменить квоты КПЭ («≥1 [SIM]») на условные правила: ставить маркер только при реальном основании; если оснований нет, писать «оснований нет», а не изобретать маркер.
- Явно указать: `[SIM]` — тоже самоотчёт, а не доступ к механизмам.
- Рекап между сессиями: только если пользователь вставил его сам; без памяти не выдумывать.
- Добавить короткий режим для простых вопросов.

### 4. Улучшения `drm-audit`
- Добавить краткий режим (если существенных проблем нет — отчёт в 3–5 строк).
- Добавить метаданные (версия, лицензия) во frontmatter.
- Не менять суть правил 1–10 без пометки в CHANGELOG.

### 5. Упаковка и документы
- README: переписать под позиционирование «проверка ИИ-отчётов», убрать акцент на сознании; оставить честные ограничения.

- `LICENSE`: оставить как есть, решение о лицензии принимает владелец.

- [ ] Скрипты работают на mock-данных, README в `eval/` объясняет запуск.
- [ ] Ключ ослепления хранится отдельно от выводов.
- [ ] `drm-contract` без квот КПЭ, с оговоркой про `[SIM]`.
- [ ] README и CHANGELOG обновлены, без заявлений об эффективности.
